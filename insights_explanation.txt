# CHALKY INFOTECH - INSIGHTS SECTION TECHNICAL DOCUMENTATION
===========================================================

This document provides a comprehensive technical overview of the Insights section, its directory layout, component structure, dynamic slugs, and backend connection mechanism.

---

## 1. DIRECTORY & PAGE STRUCTURE (FRONTEND ROUTING)
The Insights section is built using Next.js App Router and is located under the `src/app/insights` directory. It uses dynamic routing slugs to serve categories and specific posts.

### File Hierarchy:
- src/app/insights/
  ├── layout.tsx                # Shared layout wrapper for the Insights section
  ├── page.tsx                  # Main Insights landing page index (All Categories & Featured Articles)
  └── [categorySlug]/           # Dynamic category router (e.g., /insights/case-studies)
      ├── loading.tsx           # Suspense fallback skeleton for loading category page content
      ├── page.tsx              # Category landing page displaying articles under that specific category
      └── [postId]/             # Dynamic single post detail router (e.g., /insights/case-studies/123)
          ├── loading.tsx       # Suspense fallback skeleton for loading article contents
          └── page.tsx          # Single article viewer with full block-based text rendering

### Page-by-Page Overview:
1. **Main Insights Landing Page (`insights/page.tsx`)**:
   - Serves as the entryway to Chalky InfoTech's thought leadership.
   - Connects to the backend API to retrieve all publications and categories.
   - Implements a SectionNavbar for smooth page navigation across sub-sections.
   - Highlights the 3 most recent or featured posts in a 3D Stacked Carousel (`FeaturedHighlight`).
   - Renders a responsive `SidebarPublishingHub` featuring section-to-category filter lists on the left, and a paginated post grid on the right.
   - Feeds a `RecentArticles` grid showing posts that aren't highlighted in the top carousel.
   - Integrates `SectorCategories` to present all available categories inside sticky pin cards.
   - Concludes with an accordion-style `InsightsFAQ` and a `CTASection` for newsletter sign-ups.

2. **Category Page (`insights/[categorySlug]/page.tsx`)**:
   - Displays a customized view dedicated to a single category (e.g., "Blogs" or "Case Studies").
   - Resolves the matching category data and parent section dynamically from the cached site structure.
   - Leverages React Suspense and static parameters (`generateStaticParams`) to build static routes for all categories.
   - Reuses the `FeaturedHighlight` to showcase leading stories in that category, and renders the `SidebarPublishingHub` in a full-width layout without the category sidebar filter (`hideSidebar={true}`).
   - Dynamically loads a category-specific background header image from local assets (`CATEGORY_IMAGES`) depending on the slug.

3. **Post Detail Page (`insights/[categorySlug]/[postId]/page.tsx`)**:
   - Responsible for rendering a specific research piece, newsletter, or case study.
   - Extracts the `postId` from the dynamic route parameter to fetch the full post package.
   - Renders an editor-made layout mapping all API-provided CMS block objects (text, headings, pull quotes, list elements, images, and embedded documents) to their semantic Tailwind/HTML components.
   - Features a sticky sidebar showcasing a profile card for the "Lead Contributor" (author), standard social share handles, and related publications under the same parent section.
   - Employs an interactive client component called `EngagementHub` to register reader analytics (views and likes) and handle browser-level social sharing controls.

## 2. BACKEND API CONNECTION & DATA FLOW
The connection between the Next.js frontend and the Azure-hosted FastAPI backend is managed by the `ApiService` class defined in `src/services/api.ts`.

### Endpoint & Configuration Details:
- **Base URL**: `https://mediahub-backend-docker-hgh6hzgacraqbhb2.southindia-01.azurewebsites.net` (defined via `process.env.NEXT_PUBLIC_API_URL`).
- **Company ID**: `CK-666713` (defined via `process.env.NEXT_PUBLIC_COMPANY_ID`).
- **Prefix**: `/api`

### Core API Service Methods:
- `getSections()`: Fetches all corporate sections from `/api/public/{company_id}/sections`.
- `getCategories(sectionSlug)`: Fetches categories associated with a section from `/api/public/{company_id}/categories?section_slug={slug}`.
- `getContent(params)`: Retrieves posts matching optional section/category parameters with query page limits from `/api/public/{company_id}/content`.
- `getContentById(contentId)`: Requests a single content package containing editor blocks from `/api/public/content/{id}`.
- `getFullSiteStructure()`: A orchestrator that calls `getSections()`, then queries the categories for each section, and fetches the first 10 posts for each category in parallel via `Promise.all()`. This returns a fully constructed nested JSON tree of sections -> categories -> posts.
- `getAllPosts()`: Flattens the site structure generated above into a sorted array of posts based on chronological order (`date` descending).

### Request Optimizations & Caching:
1. **Deduplication**: Uses a `pendingRequests` Map. If an identical endpoint call is triggered while one is active, it returns the existing promise instead of opening a new TCP channel.
2. **In-Memory Cache**: Uses a `cache` Map to hold API responses and serve them instantly on subsequent views.
3. **Next.js Revalidation**: Uses standard fetch header `{ next: { revalidate: 60 } }` to refresh data every 60 seconds.
4. **Component-Level Cache**: Employs Next.js 16 `"use cache"` directives (`getCachedSiteStructure` and `getCachedAllPosts`) to preserve page rendering speeds on the server-side.

### Content Transformation Layer:
The API service transforms backend JSON payloads via the `transformContent()` method. It ensures:
- Date normalization (converting `published_at` or `created_at` fields into standard YYYY-MM-DD format).
- Automated Read-Time calculation (derived from block word counts divided by average reading speed, if not provided by backend stats).
- Excerpt generation (parsing text blocks to extract a snippet of up to 150 characters if no subtitle is configured).
- Asset URL resolution (generating absolute URL strings for cover images and documents to route through backend media endpoints `/api/images/{id}` and `/api/documents/{id}`).

## 3. BLOCK RENDERING SYSTEM (RICH TEXT INTERPRETER)
Inside `[postId]/page.tsx`, Chalky's frontend reads structural blocks returned from the backend CMS editor and maps them directly to high-fidelity components:

- **Heading**: Renders as `<h2>` styled with heavy black fonts (`font-extrabold text-[#1A1A1A] mt-10 mb-4`).
- **Subheading**: Renders as `<h3>` styled with Chalky's corporate purple accent (`font-bold text-[#7A1F5C] mt-8 mb-3`).
- **Text**: Renders as a standard paragraph `<p>` with appropriate spacing and text sizes (`text-gray-600 leading-relaxed text-base md:text-lg mb-6`).
- **Quote / Pull-Quote**: Renders as a distinct blockquote `<blockquote>` styled with a left accent border and cream-colored background, including author citations.
- **Lists (Bullet / Numbered)**: Maps arrays into `<ul>` or `<ol>` lists with appropriate bullet/number counts and layout spacing.
- **Image**: Renders using the Next.js optimized `<Image>` component, requesting the backend image ID. Includes styling borders and centered italic captions.
- **Document**: Renders an interactive container link showcasing a PDF file icon. Clicking the block triggers a download or preview of the document directly from `/api/documents/{file_id}`.

## 4. DYNAMIC SLUGS & CATEGORY METADATA
Category mapping is highly dynamic and adapts to configurations managed in the backend, while supporting a fall-back system on the client.

### Category Routing (`[categorySlug]`):
- Next.js fetches all available categories at build time via `generateStaticParams()` in `[categorySlug]/page.tsx`.
- The `generateMetadata()` method dynamically updates the browser title (e.g., "Blogs | Chalky Infotech Insights") and search engine metadata descriptions based on the current active slug.

### Local Assets Mapping:
To maintain high visual fidelity, a static local asset map (`CATEGORY_IMAGES`) is kept to associate category slugs with premium visuals:
- `blogs` -> `imgBlogs` (Blogs.png)
- `case-studies` -> `imgCaseStudies` (Case Studies.png)
- `testimonials` -> `imgTestimonials` (Testimonials.png)
- `company-announcements` -> `imgCompanyAnnounce` (Companny Announcement.png)
- `podcasts` -> `imgPodcasts` (Podcasts.png)
- `team-culture` -> `imgTeamCulture` (Team Culture.png)
- ...and others including community, celebrations, and newsletter images.

### Fallback Categories:
If the database contains no structured categories, the frontend falls back to a preset list of core sectors:
1. **Technology & Cloud** (`it-technology`) - Cpu icon, light blue theme.
2. **Executive & C-Suite** (`executive-search`) - Award icon, sand/gold theme.
3. **Workforce & Scaling** (`contract-staffing`) - Layers icon, purple theme.
4. **Global Remote Hiring** (`remote-hiring`) - Globe icon, light purple theme.

## 5. INTERACTIVE CLIENT-SIDE ENGAGEMENT SYSTEM
The `EngagementHub` component manages dynamic content stats without interrupting Next.js server caching:

- **Views Counter**: Computes a stable, deterministic view count based on a string hash of the unique `postId` (making counts look natural and populated).
- **Likes System**: Reads and writes liked states directly to the user's browser `localStorage` (via the key `like_{postId}`). If a user likes a post, the local state and visual counter increment by 1, and persist upon refresh.
- **Share Menu**: A Framer Motion animated dropdown displaying native sharing triggers:
  - **LinkedIn**: Opens a shared post portal.
  - **Twitter**: Launches a pre-formatted tweet dialog with the post title.
  - **Facebook**: Launches a link sharing dialog.
  - **Copy Link**: Copies the URL to the clipboard and triggers a "Copied!" checkmark confirmation.
